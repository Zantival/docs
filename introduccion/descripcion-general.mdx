FusaShop es una plataforma de comercio electrónico orientada a MiPymes colombianas, desarrollada con **Laravel 12** como núcleo principal. Reúne en un solo sistema todo lo que necesitan tres actores distintos —consumidores, comerciantes y analistas— para comprar, vender y supervisar el negocio de extremo a extremo. Cada módulo fue diseñado para operar de forma independiente pero integrada, desde la autenticación inicial hasta el análisis de datos con modelos de aprendizaje automático escritos en Python.

## ¿Qué es FusaShop?

FusaShop centraliza el ciclo de vida completo de una transacción: un consumidor explora el catálogo, agrega artículos al carrito, paga a través de PayU y luego puede dejar una reseña o abrir un PQRS. El comerciante —una MiPyme que supera el proceso KYC— administra sus productos, revisa pedidos y solicita banners publicitarios. El analista supervisa el sistema completo: aprueba KYC, gestiona usuarios, revisa reportes de ventas y ejecuta análisis de ML sobre el comportamiento de los comerciantes.

## Stack tecnológico

FusaShop usa las siguientes tecnologías principales. Puedes consultarlas en el archivo `composer.json` de la raíz del proyecto.

| Capa | Tecnología | Versión |
|---|---|---|
| Framework backend | Laravel | ^12.0 |
| Lenguaje | PHP | ^8.2 |
| Autenticación API | Laravel Sanctum | ^4.0 |
| OAuth social | Laravel Socialite | ^5.26 |
| Correo electrónico | Resend + Mailgun | ^1.4 / ^7.4 |
| Integración Python | Symfony Process | ^7.4 |
| Base de datos | MySQL | — |
| Pruebas | PHPUnit | ^11.4 |
| Entorno de desarrollo | Laravel Sail | ^1.37 |

<Note>
  El archivo `.env.example` incluye la zona horaria `America/Bogota` y localización `es_CO`, lo que refleja el enfoque del sistema hacia el mercado colombiano.
</Note>

## Los tres roles

FusaShop distingue tres tipos de usuario, cada uno con su propio espacio dentro de la aplicación:

<CardGroup cols={3}>
  <Card title="Consumer" icon="user" href="/modulos/consumidores">
    Explora el catálogo, compra productos, gestiona su carrito y sus pedidos, deja reseñas y abre PQRS.
  </Card>
  <Card title="Merchant (MiPyme)" icon="store" href="/modulos/comerciantes">
    Crea y administra productos, gestiona pedidos entrantes, solicita banners y atiende a clientes por chat. Debe superar la validación KYC.
  </Card>
  <Card title="Analyst" icon="user-tie" href="/modulos/panel-analista">
    Supervisa toda la plataforma: aprueba KYC, gestiona usuarios, revisa pagos, ejecuta ML y controla banners globales.
  </Card>
</CardGroup>

La columna `role` de la tabla `users` contiene el valor `consumer`, `merchant` o `analyst`, y el middleware `RoleMiddleware` usa ese valor para conceder o denegar acceso a cada grupo de rutas.
