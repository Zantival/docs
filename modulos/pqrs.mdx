El sistema **PQRS** (Peticiones, Quejas, Reclamos y Sugerencias) es un mecanismo de atención ciudadana y al cliente exigido por la normativa colombiana (Ley 1437 de 2011 y el Estatuto del Consumidor — Ley 1480 de 2011). FusaShop lo implementa como un canal formal para que consumidores y comerciantes puedan comunicarse con el equipo de analistas, con trazabilidad completa y notificaciones automáticas en cada cambio de estado. El modelo PQRS usa la tabla `p_q_r_s` y expone rutas para usuarios regulares y para analistas.

## Rutas del módulo PQRS

| Método | Ruta | Nombre | Rol requerido | Descripción |
|--------|------|---------|---------------|-------------|
| `GET` | `/pqrs` | `pqrs.index` | Autenticado | Listado propio del usuario |
| `GET` | `/pqrs/create` | `pqrs.create` | Autenticado | Formulario de nueva solicitud |
| `POST` | `/pqrs` | `pqrs.store` | Autenticado | Crear solicitud |
| `GET` | `/pqrs/{pqrs}` | `pqrs.show` | Autenticado | Ver detalle de una solicitud |
| `GET` | `/admin/pqrs` | `analyst.pqrs.index` | Analista | Listado global de todas las solicitudes |
| `POST` | `/admin/pqrs/{pqrs}/reply` | `analyst.pqrs.reply` | Analista | Responder y cambiar estado |

## Ciclo de vida de una solicitud PQRS

<Steps>
  <Step title="El usuario crea la solicitud">
    Desde `GET /pqrs/create`, el usuario completa el formulario con el tipo (`peticion`, `queja`, `reclamo` o `sugerencia`), un asunto (máx. 255 caracteres) y el contenido detallado (máx. 2 000 caracteres). Al enviar, el estado inicial es `pending`.
  </Step>
  <Step title="Notificación automática a los analistas">
    El sistema notifica a **todos** los analistas registrados con `NewPQRSNotification`. Cada analista recibe la notificación en su centro de notificaciones y por correo electrónico.
  </Step>
  <Step title="El analista revisa la solicitud">
    Desde `GET /admin/pqrs`, el analista ve todas las solicitudes paginadas (20 por página) con la información del usuario que las creó.
  </Step>
  <Step title="El analista responde y cambia el estado">
    A través de `POST /admin/pqrs/{pqrs}/reply`, el analista escribe una respuesta y selecciona el nuevo estado: `in_review`, `resolved` o `closed`.
  </Step>
  <Step title="Notificación al usuario">
    El sistema notifica automáticamente al usuario original con `PQRSResponseNotification`, que incluye la respuesta del analista y el nuevo estado.
  </Step>
  <Step title="Cierre y trazabilidad">
    Si el estado cambia a `resolved`, el campo `resolved_at` se registra con la fecha y hora actuales para trazabilidad.
  </Step>
</Steps>

## Flujo del usuario (consumidor / comerciante)

### Crear una solicitud

```php title="PQRSController.php — store()"
$data = $request->validate([
    'type'    => 'required|in:peticion,queja,reclamo,sugerencia',
    'subject' => 'required|string|max:255',
    'content' => 'required|string|max:2000',
]);

$pqrs = PQRS::create([
    'user_id' => Auth::id(),
    'type'    => $data['type'],
    'subject' => strip_tags($data['subject']),
    'content' => strip_tags($data['content']),
    'status'  => 'pending',
]);

// Notificar a todos los analistas
$analysts = User::where('role', 'analyst')->get();
foreach ($analysts as $analyst) {
    $analyst->notify(new \App\Notifications\NewPQRSNotification($pqrs));
}

return redirect()->route('pqrs.index')
    ->with('success', 'Tu solicitud ha sido enviada correctamente. Un administrador la revisará pronto.');
```

<Note>
  El contenido del asunto y del mensaje pasan por `strip_tags` para evitar inyección de HTML. La notificación `NewPQRSNotification` se envía a **todos** los analistas activos, no solo a uno asignado.
</Note>

### Ver el detalle de una solicitud

`GET /pqrs/{pqrs}` está protegido por autorización explícita: solo el propietario de la solicitud o un analista pueden verla. Cualquier otro intento retorna `HTTP 403`:

```php title="PQRSController.php — show()"
public function show(PQRS $pqrs)
{
    if ($pqrs->user_id !== Auth::id() && !Auth::user()->isAnalyst()) {
        abort(403);
    }
    return view('pqrs.show', compact('pqrs'));
}
```

## Flujo del analista

### Listar todas las solicitudes

`GET /admin/pqrs` devuelve todas las solicitudes de la plataforma con la información del usuario que las creó, paginadas de 20 en 20:

```php title="PQRSController.php — adminIndex()"
public function adminIndex()
{
    $pqrs = PQRS::with('user')->latest()->paginate(20);
    return view('analyst.pqrs.index', compact('pqrs'));
}
```

### Responder una solicitud

`POST /admin/pqrs/{pqrs}/reply` permite al analista escribir la respuesta, cambiar el estado y registrar la fecha de resolución si corresponde:

```php title="PQRSController.php — adminReply()"
$request->validate([
    'admin_response' => 'required|string|max:2000',
    'status'         => 'required|in:in_review,resolved,closed',
]);

$pqrs->update([
    'admin_response' => strip_tags($request->admin_response),
    'status'         => $request->status,
    'resolved_at'    => $request->status === 'resolved' ? now() : $pqrs->resolved_at,
]);

// Notificar al usuario
$pqrs->user->notify(new \App\Notifications\PQRSResponseNotification($pqrs));
```

### Parámetros del formulario de respuesta

<ParamField body="admin_response" type="string" required>
  Respuesta del analista. Máximo 2 000 caracteres. Las etiquetas HTML se eliminan automáticamente.
</ParamField>

<ParamField body="status" type="string" required>
  Nuevo estado de la solicitud. Valores válidos: `in_review`, `resolved`, `closed`.
</ParamField>

## Estados de una solicitud

| Estado | Descripción | Transición |
|--------|-------------|------------|
| `pending` | Recién creada, sin revisar | Estado inicial al crear |
| `in_review` | Un analista la está analizando | Analista cambia el estado |
| `resolved` | Fue resuelta satisfactoriamente; se registra `resolved_at` | Analista marca como resuelta |
| `closed` | Cerrada sin más acción (plazo vencido, duplicada, etc.) | Analista cierra la solicitud |

<Info>
  El campo `resolved_at` se guarda únicamente cuando el estado cambia a `resolved`. Si el analista cambia el estado a `closed` sin pasar por `resolved`, `resolved_at` permanece `null`.
</Info>

## Modelo PQRS

```php title="PQRS.php — fillable y relaciones"
protected $table = 'p_q_r_s';

protected $fillable = [
    'user_id',
    'type',
    'subject',
    'content',
    'status',
    'admin_response',
    'resolved_at',
];

public function user(): BelongsTo
{
    return $this->belongsTo(User::class);
}
```

### Campos del modelo

<ResponseField name="user_id" type="integer">
  ID del usuario que creó la solicitud. Relacionado con el modelo `User`.
</ResponseField>

<ResponseField name="type" type="string">
  Tipo de solicitud: `peticion`, `queja`, `reclamo` o `sugerencia`.
</ResponseField>

<ResponseField name="subject" type="string">
  Asunto breve de la solicitud (máximo 255 caracteres).
</ResponseField>

<ResponseField name="content" type="string">
  Descripción detallada del caso (máximo 2 000 caracteres).
</ResponseField>

<ResponseField name="status" type="string">
  Estado actual: `pending`, `in_review`, `resolved` o `closed`.
</ResponseField>

<ResponseField name="admin_response" type="string | null">
  Respuesta redactada por el analista. `null` mientras no haya respuesta.
</ResponseField>

<ResponseField name="resolved_at" type="timestamp | null">
  Fecha y hora en que la solicitud fue marcada como `resolved`. `null` en otros estados.
</ResponseField>

## Autorización

El módulo de PQRS implementa dos niveles de autorización:

- **Listado propio** (`GET /pqrs`): solo devuelve las solicitudes del usuario autenticado (`WHERE user_id = auth()->id()`).
- **Detalle** (`GET /pqrs/{pqrs}`): el controlador verifica explícitamente que `$pqrs->user_id === Auth::id()` o que el usuario sea analista. De lo contrario, ejecuta `abort(403)`.
- **Panel de analista** (`GET /admin/pqrs`): protegido por el middleware `role:analyst`. Muestra **todas** las solicitudes de la plataforma.

<Tabs>
  <Tab title="Vista del usuario">

  <Tab title="Vista del analista">
